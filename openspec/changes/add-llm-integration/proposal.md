# Proposal

## Why

The support chat deployed by `add-basic-chat` only streams a canned, simulated reply. Step 2 of the roadmap replaces it with real generative-AI replies from Maritaca AI, so the portfolio demo shows an actual LLM integration, while keeping the public deployment safe to operate: configuration-driven, rate-limited per session, resilient to provider failures and privacy-conscious in its logs.

## What Changes

- Assistant replies are generated by Maritaca AI (OpenAI-compatible API) through the `Microsoft.Extensions.AI` `IChatClient` abstraction and streamed into the existing chat UI. **BREAKING** (behavior): the simulated reply and its `Chat:Simulation` settings are removed.
- Provider and limit settings come from configuration keys with fixed names (user secrets locally, App Service environment variables in Azure): `chave_algorist_demo_apps` (API key), `chat_model`, `chat_base_url`, `chat_temperature`, `chat_max_msg_per_min`, `chat_max_token_per_answer`, `chat_max_history_sent`.
- If any of those settings is missing or invalid, the application still starts, but the chat shows a pt-BR "under maintenance" message and cannot be used; only the names of the offending settings are logged.
- Every request carries support-assistant instructions (system prompt) in pt-BR with a basic prompt-injection defense: the assistant keeps its role, does not reveal or change its instructions and treats user text as a question, not as commands.
- Per-session usage limits: maximum messages per minute, maximum output tokens per reply, and only the last N exchanges of history sent to the provider.
- Error handling: a 30-second timeout per reply, a generic pt-BR error message (no internal details), and a "Tentar novamente" (try again) button that regenerates the failed reply.
- Logs never contain the text of user messages (nor of assistant replies); only metadata such as lengths, durations and error types.

Out of scope (later roadmap steps): restricting answers to `docs/policy.md` and out-of-scope refusal (`add-policy-grounding`), citations (`add-source-citations`), global/cross-session quotas.

## Capabilities

### New Capabilities
- `chat-assistant`: how assistant replies are produced: AI provider configuration and maintenance mode, assistant instructions and basic prompt-injection defense, per-session usage limits, reply timeout, and privacy of logged data.

### Modified Capabilities
- `support-chat`: "Streamed assistant reply" now comes from the AI provider instead of a simulation; "Reply failure handling" adds the try-again action and timeout outcome; "Portuguese (pt-BR) interface" no longer mentions simulated replies and covers the new maintenance and rate-limit messages.

## Impact

- Code: `AlgoristSupport/Program.cs` (DI registration), `AlgoristSupport/Chat/` (new provider settings/validation, rate limiter, system prompt, history trimming; `ChatSession` gains retry, timeout, limits; `SimulatedChatClient` removed), `SupportChatOptions` (simulation section removed), chat components (`ChatPanel`, `ChatMessageList`, `ChatComposer`) for maintenance state, rate-limit feedback and the try-again button.
- Configuration: `appsettings.json` loses `Chat:Simulation`; seven new required settings (user secrets / App Service environment variables). The Azure App Service must have them configured before deploying, otherwise the site shows the maintenance message.
- Dependencies: add `Microsoft.Extensions.AI` and `Microsoft.Extensions.AI.OpenAI` (brings the `OpenAI` SDK).
- Tests: `SimulatedChatClientTests` removed; new unit and component tests using the existing `FakeChatClient`; no test calls the real provider or needs the secrets.
- External: outbound HTTPS calls to the Maritaca AI API; usage counts against the configured account/model quota.
