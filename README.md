# Algorist Support Demo App

A pt-BR support chat demo (Blazor Web App, .NET 10, Interactive Server).
Replies are generated by [Maritaca AI](https://www.maritaca.ai/) (OpenAI-compatible API) through the
`Microsoft.Extensions.AI` `IChatClient` abstraction and streamed to the screen.
The assistant answers only from the fictional service policy in [`docs/policy.md`](docs/policy.md), which
visitors can also read at `/politica`.


## Chat features

- Header with the assistant name and a permanent "demo / fictional policy" notice; "política fictícia" links to
  the policy page (`/politica`), opening in a new tab.
- Message list with auto-scroll, streamed replies, a "Gerando resposta…" indicator and a **Parar** button.
- **Enter** sends, **Shift+Enter** inserts a newline; empty/whitespace-only messages are not sent.
- Character counter with a configurable limit (default 500); sending is blocked while a reply is in progress.
- **Nova conversa** clears the history; suggested-question chips appear while the conversation is empty.
- History is kept in memory per browser tab session (Blazor circuit) only: no database, no sign-in. Reloading starts fresh.
- Assistant replies are rendered as Markdown (raw HTML escaped, only http/https/mailto links kept, plus the
  app-built policy citation links below); user messages are shown as plain text.
- Every request starts with pt-BR support-assistant instructions including a basic prompt-injection defense.
- Per-session limits: messages per minute, output tokens per reply, and how many previous exchanges are sent.
- A reply that fails or takes longer than 30 seconds shows a generic error and a **Tentar novamente** button.
- Logs contain only metadata (durations, counts, token usage, error type/status), never message text.

## Policy grounding

- [`docs/policy.md`](docs/policy.md) is the single source of the (fictional) policy. The web project links it as
  content, so it is copied to the build and publish output as `Policy/policy.md` and deployed with the app.
- It is loaded once at startup. Every request's system message holds the grounding rules followed by the full
  policy between `<politica>` and `</politica>`: the assistant answers only from it, says when something is not
  covered (pointing to the policy's contact e-mail), declines off-topic questions and treats the policy as data.
  The whole document (about 6k tokens) is sent; there is no retrieval/RAG step.
- `/politica` renders the same file as a page. Editing the policy requires a redeploy (or restart).
- If the file is missing or empty, the chat enters maintenance mode (below), `/politica` shows an "indisponível"
  message, and a startup warning identifies the file (never its content).

## Source citations

- The system prompt asks the assistant to cite the policy sections it used inline as `(Seção N)`, the same style
  as the policy's own FAQ, and not to cite anything for uncovered or off-topic questions.
- Once a reply finishes streaming (or is stopped), citations such as `Seção 12`, `Seção 12.1` and `Seções 12 e 13`
  become links to that section of `/politica`, opening in a new tab so the conversation is kept. The link's
  accessible name includes the section title.
- Links are **section-level only**: `Seção 12.1` links to section 12. A number that is not a section of the loaded
  policy (e.g. `Seção 99`) stays plain text. Citations in user messages, code and existing links are never linked.
- The model never writes the URLs: the app builds them from the policy's numbered headings (`## N. Title`), and
  each numbered heading on `/politica` gets the title-independent anchor `secao-N`, highlighted when targeted.

## Look and feel

- The UI follows the visual identity of [algorist.com.br](https://algorist.com.br): a dark top bar with the gold
  Algorist logo (linking to the company site in a new tab), gold `#ffc451` accents, Raleway headings, Roboto body
  text, Poppins buttons and Roboto Mono code.
- Colors and fonts are design tokens (CSS custom properties) at the top of
  [`wwwroot/app.css`](AlgoristSupport/wwwroot/app.css). Bootstrap is themed through its own CSS variables, with no
  Sass build. The bright gold is never used as text on light backgrounds; a darker gold keeps links at WCAG AA contrast.
- Fonts are self-hosted in [`wwwroot/fonts`](AlgoristSupport/wwwroot/fonts) under the SIL Open Font License
  ([`OFL.txt`](AlgoristSupport/wwwroot/fonts/OFL.txt)), so pages make no third-party font requests.
- A test (`BrandStyleTests`) fails if a default template blue comes back into the app's stylesheets.

## AI provider settings (required)

These seven settings are read by **exact name** from the root of the configuration. They have no defaults and
must never be committed.

| Setting | Meaning | Valid value |
| --- | --- | --- |
| `chave_algorist_demo_apps` | Maritaca AI API key | non-empty text |
| `chat_model` | Model identifier | non-empty text, e.g. `S5-free` |
| `chat_base_url` | Provider base URL | absolute `https` URL, e.g. `https://chat.maritaca.ai/api` |
| `chat_temperature` | Sampling temperature | number from `0` to `2`, `.` as decimal separator (e.g. `0.3`) |
| `chat_max_msg_per_min` | Messages per minute per session (sends, suggestions and retries) | integer >= 1 |
| `chat_max_token_per_answer` | Maximum output tokens per reply | integer >= 1 |
| `chat_max_history_sent` | Previous exchanges sent with each request | integer >= 0 (`0` = only the current message) |

**Local development** (user secrets, from the `AlgoristSupport/` project folder):

```bash
dotnet user-secrets set "chave_algorist_demo_apps" "<your-api-key>"
dotnet user-secrets set "chat_model" "<model-id>"
dotnet user-secrets set "chat_base_url" "https://chat.maritaca.ai/api"
dotnet user-secrets set "chat_temperature" "0.3"
dotnet user-secrets set "chat_max_msg_per_min" "5"
dotnet user-secrets set "chat_max_token_per_answer" "800"
dotnet user-secrets set "chat_max_history_sent" "10"
```

**Azure App Service**: add the same seven names under *Settings > Environment variables* and restart the app.

**Maintenance mode**: if any setting is missing or invalid (or the policy file cannot be loaded), the app still starts, the chat shows
"O chat está em manutenção" and no message can be sent. A startup warning names the offending settings
(never their values) or identifies the policy file.

## UI configuration

`AlgoristSupport/appsettings.json`, section `Chat`:

| Key | Default | Description |
| --- | --- | --- |
| `AssistantName` | `Assistente de Suporte` | Name shown in the top bar next to the logo and in screen-reader labels. |
| `MaxMessageLength` | `500` | Maximum characters per message (1–4000). |
| `ReplyTimeoutSeconds` | `30` | A reply not completed within this time is cancelled and shown as failed (1–600). |
| `SuggestedQuestions` | 4 policy questions | Chips shown on an empty conversation (empty list hides them). |

Invalid values fail at startup. Any key can be overridden with environment variables, e.g. `Chat__MaxMessageLength=300`.

## Tests

```bash
dotnet test AlgoristSupport.slnx
```

Tests use a fake `IChatClient` and a fake clock: they need no secrets and make no network calls.
